# M10:采样感知草稿——离线估计,闸门未达到,实现推迟

日期:2026-10-25 · 对应 CHECKPOINT-003 路线图 M10。

## 1. 想法

采样模式(默认温度 1.0、top-k 20、top-p 0.95、min-p 0.05)下,现在的投机采样是:MTP 头出一个**确定性**草稿 `d = argmax q`,目标分布 `p` 采样一个 `s0`,`s0 == d` 才接受,接受概率 = `p(d)`。ninfer 的 DFlash2 合同给出了另一种做法:草稿从自己的分布 `q` 里**采样**,以 `min(1, p(d)/q(d))` 接受,拒绝时从残差 `max(p−q, 0)` 重采样。两者都保持输出分布不变,但后者的接受概率是 `Σ_v min(p(v), q(v)) = 1 − TV(p, q)`,当 q 接近 p 时远高于 `p(argmax q)`。

## 2. 离线估计(`kata mtp-accept`)

模型用真实采样器生成 200 个 token,每个位置同时算 MTP 的 `q` 和目标的 `p`(都经过 top-k/top-p/min-p/温度),比较两种接受率:

| 文本 | 确定性草稿 | 从 q 采样 | top-1 一致 |
|---|---|---|---|
| 散文(无思考) | 53.6% | 60.5% | 60.5% |
| 代码(无思考) | 85.2% | 86.5% | 87.0% |
| 推理(思考) | 71.9% | 75.7% | 75.0% |
| 讲解(无思考) | 58.2% | 67.5% | 62.0% |
| **全部(800 个位置)** | **67.2%** | **72.5%** | 71.1% |
| 温度 0.6,全部 | 70.1% | 72.6% | 72.4% |

每周期 token 数 1.67 → 1.73(+3.6%);扣掉每周期多做的两次 CPU 采样(单遍 top-K 后约 0.1–0.3 ms),净收益约 **+2–3%**,只出现在采样模式。

## 3. 结论

闸门(采样模式接受率提升 ≥ 9 个点)**没有达到**:只有 +5 个点(散文 +7,代码 +1)。收益 +2–3% 大于 1% 的保留线,但低于其它里程碑,所以**暂不实现**,留作可选项(M17)。

若以后实现,需要:① `spec.cpp` 的草稿步用 `samplerDistribution` 得到 `q` 并从中采样 `d`(MTP 的 logits 已经在 `eng.logits()`);② 验证步对 `p0` 做 `min(1, p0(d)/q(d))` 检验,拒绝时在 `supp(p)∪supp(q)` 上按 `max(p−q, 0)` 重采样;③ 接受后的第二个 token 照旧从 `p1` 采样;④ 用一个不需要 GPU 的单元测试验证分布:对合成的 `(p, q)` 重复百万次,输出的经验分布应与 `p` 一致(卡方检验)。

## 4. 随带的改动(已合入)

- `samplerDistribution` / `sampleFromDist`:采样器返回稀疏分布;`sampleToken` 行为位级不变(固定种子的输出与重构前逐字相同,贪心/采样、开/关投机都验证过)。
- top-K 改成单遍(`K ≤ 64` 时),不再对 248K 个下标做 `partial_sort`:算法上 O(n),在 P 核上约 0.1 ms。
- 观察:CPU 采样耗时在 0.1–0.9 ms/周期之间随机跳动,很可能是线程被调度到了能效核上。M17 可以试 `pthread_set_qos_class_self_np(QOS_CLASS_USER_INTERACTIVE)` 看能否稳定在 P 核上。
